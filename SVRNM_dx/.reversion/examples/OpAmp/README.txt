DISCUSSION:

The command "run-op" will set up the EEnet Op Amp simulation and start 
SimVision.  You may need at least Xcelium 18.03 for these to work properly.
Press the "run" button to execute the simulation;
Choose File->Source Command Script and then select file "simv-eeop.svcf" to 
plot a reasonable set of outputs for the simulation.
Note that most parameter setup is done in the opamp_tb.sv file.  Specifically,
the timestep size is set to 20ns, which is the largest stepsize that will work
when the op amp is in unity gain configuration (Rf small).  In fact, you may
get a message about one unconverged timestep at the point where it steps to
RF=1 (just after 9us) -- after 20 iterations it still hasn't converged to 0.1mV
accuracy so it prints the warning message there.  If you change the tinc value 
to 10ns it would then take twice as many timesteps, but converge much more 
rapidly even in the unity gain range (no more than 6 iterations per timestep).

The analog feedback in the model is causing the iterations to occur:  A change
in output voltage results in a change of feedback, changing the input voltage,
so it changes the output voltage again.  But the smaller the timestep, the 
smaller the effective resistance to ground of the dominant pole capacitor 
equivalent model over that step, resulting in smaller input change for each 
output change and thus faster iteration to the final solution.  With higher
gain systems, only a small fraction of the output signal is being feed back,
so convergence only takes a few iterations with very little dependence on the
time constant.  But the unity gain case puts all hope of converging iterations
into the time constant characteristic without any other attenuation to help 
out, hence the strong dependence of timestep size on iterations needed for
that combination.

The ClipV module is used to bound the voltage on the midnode to be between the
power supply limits:  It effectively shorts the node (N1) to the respective 
supply through a small resistance when it is driven past the specified supply
level.  This low impedance short immediately results in the capacitor being 
discharged to match the supply value.  Note this only works properly using the
"bigstep" reformulation in the CapGeq model so that it doesn't require tiny
timesteps to perform that discharge operation.  The standard capacitance 
formulation would result in large oscillations and/or nonconvergence in the 
presence of the low impedance switching operation. 

The command "run-opa" likewise runs equivalent Verilog-AMS electrical models,
and the "simv-opa.svcf" file produces equivalent output results.  If you wish
to compare results, you can run one of the sets and copy the "waves.shm" 
directory to another directory, then run the other simulation, and load in
both sets of plot results so that you can access both waveform sets from the 
same simvision session to plot as you like (as was done in the screenshots 
in the presentation).
